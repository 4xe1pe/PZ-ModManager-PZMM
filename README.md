# Project Zomboid Mod Manager

> **Note:** this application was created with AI (**Claude by Anthropic**). The code was generated by the AI and directed by the repository owner. It is not hand-written software, so expect rough edges and please report any bug you find.

Project Zomboid Mod Manager is a Windows desktop application (built with Electron) for managing Project Zomboid mods across separate Build 41 and Build 42 profiles and instances. It downloads Workshop mods using SteamCMD anonymous login, keeps each instance's mod library separate, and safely switches the Mods folder used by the game when launching.

## Getting the app

If you only want to use the app, download the ready-made `.exe` from the **Releases** page of this repository. You do not need to build anything.

If you want to build it yourself or work on the code, follow the steps below.

## Requirements

* Windows 10 or 11
* [Node.js](https://nodejs.org/) LTS (version 18 or newer). `npm` is included with Node.js.
* An internet connection (the first build downloads Electron and the build tools)

> `node_modules/` and `dist/` are not part of the repository. They are created on your machine by the steps below.

## Quick build (recommended): `MAKE_EXE.bat`

1. Clone or download this repository and open the project folder (the one that contains `package.json`).
2. Double-click **`MAKE_EXE.bat`**.
3. Accept the administrator prompt. `electron-builder` needs it to create the executable.
4. Wait for the script to finish. It will:
   1. check that Node.js is installed (if it is missing, it installs it with `winget`; in that case close the window and run the script again),
   2. run `npm install`,
   3. build a **portable `.exe`** with the app icon.
5. When it is done, the `dist` folder opens automatically. The `.exe` inside it is the finished app: you can move it anywhere and run it with a double click.

### Troubleshooting

* **The icon is the default Electron one.** The script retries the build without editing the icon when the first attempt fails. To get the custom icon, enable *Developer Mode* in Windows (Settings → For developers) and run `MAKE_EXE.bat` again.
* **Build errors about `winCodeSign`.** The script already clears that cache. Run it again with administrator rights.
* **Anything else.** Copy the text shown in the window and open an issue.

## Manual build (command line)

Open a terminal in the project folder and run:

```bash
npm install
```

Then pick what you need:

| Goal | Command | Result in `dist/` |
| --- | --- | --- |
| Run the app in development mode | `npm start` | nothing, the app just opens |
| Build an installer (NSIS) | `npm run dist` | `Setup` `.exe` installer, with a choice of install folder |
| Build a portable `.exe` (same as `MAKE_EXE.bat`) | `npx electron-builder --win portable` | single `.exe`, no installation |

If the build fails on code signing or on the icon, run the command in a terminal opened as administrator, or enable Windows Developer Mode.

## Launching the game
* **▶ Launch Project Zomboid** (top of the right-hand panel). The executable is detected from the game folder; use
  **Select executable…** to pick `ProjectZomboid64.exe` manually. The path is saved per version profile.
* Order: (1) the selected instance is activated, (2) Steam is started **only if `steam.exe` is not already running**
  (the app waits until Steam has logged in, up to 60 s), (3) `ProjectZomboid64.exe` is started **directly** as its own
  detached process (working directory = game folder). The game is never started through Steam.
* Steam is located via the Windows registry, the game folder (`...\Steam\steamapps\common\...`) or the default folders;
  override it in Settings → *Select steam.exe…*.

## Instances
An instance = its own folder with a `mods` folder (what the game sees) and a `library` folder (downloads + index).
Instances belong to a version profile (Build 41 / Build 42). Use the bar above the tabs to **select, create, rename,
delete** them; every instance has its own mod list, downloads, update state and pushed mods.
* **Download** assigns the mod to the selected instance, **Push** installs into the selected instance's `mods` folder,
  **Remove** acts on the selected instance only. Existing users get a `Default` instance containing their old library.
* Storage folders can be chosen when creating an instance (default: `<library>\Instances\<profile>\<name>`).

### How switching works (and why)
Project Zomboid reads local mods from `%UserProfile%\Zomboid\mods` and has no setting for another mods folder
(the `-cachedir` launch option would also move saves/options, which is not wanted). So the manager turns
`Zomboid\mods` into a **directory junction** pointing at the selected instance's `mods` folder, right before launch.
Saves, options and the rest of `Zomboid` stay shared; the mod-menu list (`default.txt`) is per instance.

Safety rules: a real, non-empty `Zomboid\mods` is never deleted - you choose to *import* it into the instance and/or keep
it; either way it is renamed to `mods.pzmm-backup-<date>` beside it. Links are removed without touching their target;
a link that this app didn't create is never replaced; each switch is verified by writing a probe file through the link
and is rolled back on any error. Switching is refused while the game is running. Deleting an instance requires a marker
file written by this app, is refused for the instance currently active in the game, and can keep the files.

Notes: junctions need an NTFS drive (no admin rights required). Mods you are *subscribed to in Steam* are loaded by the
game from the Workshop folder regardless of instance - unsubscribe in Steam if you want a truly vanilla instance.
Use **Activate now** to switch the game's Mods folder without launching.
